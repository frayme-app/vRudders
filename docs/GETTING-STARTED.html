VRudders

Rudder Control · Your pedals. Your response.

0.2.0 beta · Windows 11 x64 · Virtual yaw

Get flying

  1. Connect the pedals in PC mode. Select VelocityOne Rudder and axis Z.
  2. Start with VRudders · Original response. Move the pedals. The first dot shows raw input; the second shows processed yaw.
  3. Click START. The third dot reads the virtual Z axis independently through Windows.
  4. In the flight or HOTAS controls of your game, bind yaw left/right to VRudders Yaw. An older installed driver may still appear as VRudders POC; the app accepts both.
  5. Check left, right, neutral, and full travel in a flight. Recheck bindings after a driver upgrade.

Keep VRudders running while flying. Minimize normally or enable minimize-to-tray. Closing or stopping centers yaw. Nothing starts forwarding automatically.

The large green START button turns red and reads STOP while output is live. Stop returns yaw to center.

Tuning and profiles

Stop forwarding, open Tuning & profiles, and Duplicate the protected profile or create a New one. Name it for a game or aircraft. Uncheck Bypass tuning to enable processing. Edits preview beside the live graph; Apply & save makes them active. Unsaved edits block forwarding. Reset draft discards unsaved edits.

  • Calibration: in Device calibration, release and capture center, then hold and capture each stop. Save, then enable calibration in the profile. This affects VRudders only. Calibration is stored with the device/axis, not exported with a flight profile.
  • Center/end dead zones: remove resting drift or shorten the travel required for full output. End zones are linked initially; uncheck Link to adjust independently.
  • Response curve: negative values give stronger yaw with less pedal travel; zero is linear; positive values soften the center. At −100%, 25% travel produces about 58% yaw. Both directions retain full endpoints.
  • Sensitivity / yaw strength: reduces maximum output. Keep 100% for full rudder authority.
  • Smoothing: 0 disables it; up to 200 ms adds filtering and response delay. The value is a filter time constant, not measured game latency.
  • Precision: optional hold key (F8 by default) blends toward a softer curve over 300 ms. Choose a key unbound in the game.
  • Trim: optional F9/F10 adjusts left/right by 1%, F11 resets. Buttons are also available. Trim is capped at ±20%, eases at 10% per second, and resets on Stop or profile change.
  • Import/export: shares validated JSON tuning profiles. Hardware calibration stays local.

The blue graph line shows static response; the orange dot includes smoothing, precision, and trim. Use a linear response in the game, where possible, when evaluating app curves. Return to VRudders · Original response for the original response. Reverse direction also works in bypass in a duplicated profile.

Reconnect and tray

Input loss stops forwarding and centers yaw. The app searches for the same device; verify movement and resume manually after reconnection. A changed or ambiguous identity requires Refresh and manual selection. The tray menu offers Show, Stop forwarding, and Exit. Closing the window exits; there is no automatic startup forwarding.

Troubleshooting

  • Z missing in the old beta: version 0.2.0 uses a DirectInput fallback when WinMM reports no VelocityOne Z. The selected controller shows its input backend.
  • No physical movement: check USB/PC mode, Refresh, and axis selection.
  • First two dots move, third does not: Press START. If the driver is unavailable, close all copies and rerun Setup. Save the exact error.
  • All dots move but the game does not: check HOTAS binding/conflicting axes; test Steam Input disabled for that game if needed.
  • Start disabled: apply or reset unsaved edits; save calibration if enabled. Duplicate the protected profile to edit it.
  • Another copy running: close it, including the old POC. Never run the old POC alongside this app.
  • Settings error: invalid settings are kept and the app falls back to its protected preset. Back up and repair/move %LOCALAPPDATA%\VRudders\settings.json to enable saving.

Upgrading

Setup replaces the existing app and updates the same virtual controller. It migrates the exact old Windows label to VRudders Yaw, while preserving custom names and user profiles/calibration. Restart games to reload their controller lists. Verify bindings after upgrading; games that cache names may need reassignment. The first settings migration keeps a settings-v1-backup-*.json backup.

Windows prompts and installation

Setup/removal require administrator permission; normal use does not. Official signed releases use publisher Ermis Catevatis. A new download can still receive SmartScreen reputation warnings. Verify the official source and publisher before choosing More info / Run anyway, if offered.

Windows Security may also ask to install device software from Ermis Catevatis. Review the publisher and choose Install to continue. This can happen again on an upgrade with a new signing certificate. Error 0xE0000242 means publisher approval is needed: run the latest Setup normally, without /S, to allow the prompt.

Stop for an invalid signature, unexpected publisher, or antivirus detection. Do not disable Secure Boot, memory integrity, antivirus, or driver-signature enforcement, and do not import a root certificate. Setup failures are logged to C:\Program Files\VRudders\driver-setup.log; Windows also logs driver setup in C:\Windows\INF\setupapi.dev.log.

Uninstall

Close the app and use Windows Settings → Apps → Installed apps → VRudders → Uninstall. Physical pedals stay installed. The signed package remains inactive in Driver Store. Local profiles/calibration remain in %LOCALAPPDATA%\VRudders; remove that folder yourself to clear them.

Scope

One virtual yaw axis; no toe-brake output, game injection, telemetry upload, or automatic profile switching. Function-key shortcuts only in this beta. VelocityOne is the only flight-tested hardware, from the original POC; the new build requires flight acceptance. Other standard WinMM controllers are selectable but unverified.
